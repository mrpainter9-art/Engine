# 엔진 계획

## 목표
혼자서 가벼운 2D 도트 게임을 만들 수 있는, 나에게 맞춘 작은 엔진.
특정 게임을 기준으로 삼지 않고, 가벼운 게임이라면 대부분 필요한 기본기부터 쌓아요.

## 왜 다시 시작하나
첫 시도는 에디터, 서버, AI 연결까지 한 번에 만들어서 무엇이 왜 돌아가는지 따라가기 어려웠어요.
그래서 질문도 검증도 막연해졌어요. 이번에는 작은 것부터 하나씩, 이해하면서 쌓아요.

## 일하는 방식
1. 단계마다 시작 전에 "이게 되면 끝"을 한 줄로 정해요.
2. Claude가 만들고, 코드 속 구조보다는 "화면에서 무엇이 보이고, 무엇을 바꿀 수 있고, 어디에 쓰이는지"로 설명해요.
3. 단계마다 설치 없이 바로 열어 보는 놀이터 링크를 줘요. 친구가 값을 움직여 보며 직접 확인해요.
4. 끝나면 아래 표에 완료 표시하고, 정한 것이 있으면 "결정 기록"에 적어요.

## 구조 원칙
- **코어는 아주 작게**: 루프를 돌리고 모듈을 등록받는 일만 해요.
- **기능 하나 = 폴더 하나 = 모듈 하나**: 빼고 싶으면 등록 한 줄만 지우면 돼요.
- **모듈끼리 직접 부르지 않기**: 코어를 거쳐서 주고받아요. 하나를 고쳐도 다른 게 안 깨져요.
- **값은 데이터 파일에**: 노선, 속도, 색 같은 값은 코드가 아니라 JSON에 둬요. 기획자가 직접 만지는 부분이에요.

## 도구
TypeScript + 브라우저(Canvas 2D). 설치할 게 적고, 저장하면 바로 화면에서 확인되고, 만든 게임을 링크 하나로 바로 나눠 줄 수 있어요.

## 지금 구조
```
src/
  main.ts            모듈을 등록하는 곳 (기능 하나 = 한 줄)
  settings.json      게임 전체 설정 (화면 크기, 확대 방식, 바깥 여백 색)
  controls.json      조작 설정: 어떤 키가 어떤 동작(왼쪽, 오른쪽, 행동...)인지
  core/engine.ts     코어: 모듈 목록 + 게임 루프
  core/screen.ts     작은 화면을 창 크기에 맞춰 선명하게 확대
  core/input.ts      키보드와 마우스 읽기 (게임은 키 대신 동작 이름으로 물어봄)
  core/assets.ts     그림 불러오기: assets 폴더의 그림을 파일 이름으로 바로 사용
  core/module.ts     모듈이 지켜야 할 약속 (init, update, draw)
  modules/ground/    하늘색과 바닥 타일 그림을 깔기 (값은 ground.json)
  modules/player/    연습용 캐릭터: 방향키로 이동, 가는 쪽을 바라봄, 클릭한 곳으로 이동 (값은 player.json)
assets/              그림 파일을 넣는 곳
```

## 단계
| # | 단계 | 배우는 것 | 이게 되면 끝 | 상태 |
| --- | --- | --- | --- | --- |
| 0 | 준비 | 프로젝트 폴더, 실행 방법 | 브라우저에 빈 화면이 뜬다 | 완료 |
| 1 | 게임 루프 | 1초에 60번 "계산하고 그리기", 경과 시간(dt) | 네모가 일정한 속도로 움직인다 | 완료 |
| 2 | 화면 | 작은 도트 화면(기본 320x180)을 깨지지 않게 확대 | 창 크기를 바꿔도 도트가 선명하다 | 완료 |
| 3 | 입력 | 키보드, 마우스 상태 읽기 | 화살표 키로 네모가 움직인다 | 완료 |
| 4 | 에셋 | 이미지 불러오기, 준비될 때까지 기다리기 | 그림 한 장이 화면에 나온다 | 완료 |
| 5 | 오브젝트 | 화면 속 "것"을 담는 틀(위치, 그리기, 할 일) | 여러 오브젝트가 각자 움직인다 | |
| 6 | 카메라 | 화면보다 큰 세상을 따라가며 보여 주기 | 움직이는 대상을 화면이 따라간다 | |
| 7+ | 필요할 때마다 | 대사, 소리, 시간과 날씨, 저장, 에디터 | 단계마다 따로 정해요 | |

## 결정 기록
- 2026-10-19: 그림은 assets 폴더에 넣기만 하면 파일 이름으로 쓴다(목록 파일 없음). 없는 그림은 분홍 네모와 빨간 안내 띠로 알려 주고 게임은 멈추지 않는다.
- 2026-10-19: 게임은 키를 직접 묻지 않고 "동작 이름"(left, action...)으로 묻는다. 키 배치는 controls.json에서 바꾼다. 한 동작에 키 여러 개 가능.
- 2026-10-19: 확대 방식은 두 가지. sharp(정수배, 기본값: 도트가 모두 같은 크기, 가장자리에 여백) / fill(창에 꽉 차게, 도트 크기가 미세하게 고르지 않을 수 있음).
- 2026-10-19: 특정 게임(예전 기차 게임)이나 다른 엔진(Godot)을 기준으로 삼지 않는다. 화면 크기도 설정값으로 두고 기본은 320x180.
- 2026-10-19: PR과 커밋 설명은 한국어로. 설명은 사용하는 사람 입장에서.
- 2026-10-19: 실행 도구는 Vite(저장하면 화면이 바로 바뀜) + TypeScript 두 가지만. 모듈은 init, update(dt), draw 세 순간에 끼어든다.
- 2026-10-19: 기존 엔진과 에디터를 지우고 처음부터 다시 시작. 에디터는 맨 마지막에.
