# 엔진 계획

## 목표
혼자서 가벼운 2D 도트 게임을 만들 수 있는, 나에게 맞춘 작은 엔진.
특정 게임을 기준으로 삼지 않고, 가벼운 게임이라면 대부분 필요한 기본기부터 쌓아요.

## 왜 다시 시작하나
첫 시도는 에디터, 서버, AI 연결까지 한 번에 만들어서 무엇이 왜 돌아가는지 따라가기 어려웠어요.
그래서 질문도 검증도 막연해졌어요. 이번에는 작은 것부터 하나씩, 이해하면서 쌓아요.

## 일하는 방식
1. 단계마다 시작 전에 "이게 되면 끝"을 한 줄로 정해요.
2. Claude가 만들고, 코드 속 구조보다는 "화면에서 무엇이 보이고, 무엇을 바꿀 수 있고, 어디에 쓰이는지"로 설명해요.
3. 단계마다 설치 없이 바로 열어 보는 놀이터 링크를 줘요. 친구가 값을 움직여 보며 직접 확인해요.
4. 끝나면 아래 표에 완료 표시하고, 정한 것이 있으면 "결정 기록"에 적어요.

## 구조 원칙
- **코어는 아주 작게**: 루프를 돌리고, 모듈을 등록받고, 장면을 바꾸는 일만 해요.
- **기능 하나 = 폴더 하나 = 모듈 하나**: 빼고 싶으면 등록 한 줄만 지우면 돼요.
- **모듈끼리 직접 부르지 않기**: 코어를 거쳐서 주고받아요. 하나를 고쳐도 다른 게 안 깨져요.
- **값은 데이터 파일에**: 노선, 속도, 색 같은 값은 코드가 아니라 JSON에 둬요. 기획자가 직접 만지는 부분이에요.

## 도구
TypeScript + 브라우저(Canvas 2D). 설치할 게 적고, 저장하면 바로 화면에서 확인되고, 만든 게임을 링크 하나로 바로 나눠 줄 수 있어요.

## 지금 구조
```
src/
  main.ts            모듈과 블록을 등록하는 곳 (기능 하나 = 한 줄)
  settings.json      게임 전체 설정 (제목, 화면 크기, 확대 방식, 소리 크기, 첫 장면, 저장 이름)
  controls.json      조작 설정: 어떤 키가 어떤 동작(왼쪽, 점프, 행동...)인지
  kinds.json         물건 종류: 그림(애니메이션) + 행동 블록 목록 (설명은 docs/BLOCKS.md)
  scenes/*.json      장면 하나 = 파일 하나: 맵 크기, 하늘색, 음악, 글자, 규칙, 다음 장면, 물건 배치 (docs/SCENES.md)
  behaviors/         행동 블록 (블록 하나 = 파일 하나)
  core/engine.ts     코어: 모듈 목록 + 게임 루프 + 장면 바꾸기
  core/module.ts     모듈이 지켜야 할 약속 (init, enter, update, draw)
  core/screen.ts     작은 화면을 창 크기에 맞춰 선명하게 확대
  core/input.ts      키보드와 마우스 읽기 (게임은 키 대신 동작 이름으로 물어봄)
  core/assets.ts     그림 불러오기: assets 폴더의 그림을 파일 이름으로 바로 사용, 타일 반복, 애니메이션 장
  core/sound.ts      소리: assets/sounds 폴더의 소리를 이름으로 재생, 배경 음악 반복
  core/scenes.ts     scenes 폴더의 장면 파일을 모두 찾아 이름으로 쓰게 함
  core/save.ts       최고 기록처럼 창을 닫아도 남는 숫자 저장
  core/world.ts      물건 목록: 장면대로 놓고, 블록대로 움직이고, 닿았는지, 단단한 것에 막히는지
  core/camera.ts     카메라: 넓은 맵에서 화면에 보일 부분을 정함, 맵 밖은 안 보여 줌
  core/text.ts       화면에 한글 도트 글자 쓰기 (갈무리9 글꼴, 2배 3배 크기)
  core/warn.ts       문제가 생기면 화면 위 빨간 띠로 쉽게 알려 주기
  modules/background/ 하늘색 칠하기
  modules/texts/     장면의 글자 쓰기 (타이틀 문구, 최고 기록)
  modules/rules/     게임 규칙: 무엇을 모으면 클리어, 제한 시간, 화면 문구, 기록 (rules.json)
  modules/music/     장면의 배경 음악 틀기
  editor/            편집 도구 (개발할 때만 켜짐, 내보낸 게임에는 없음) (docs/EDITOR.md)
assets/              그림 파일 (fonts/ 글꼴, sounds/ 소리)
tools/               내보내기(export.mjs), 편집 도구의 저장 창구(editor-server.ts)
```

## 단계
| # | 단계 | 배우는 것 | 이게 되면 끝 | 상태 |
| --- | --- | --- | --- | --- |
| 0 | 준비 | 프로젝트 폴더, 실행 방법 | 브라우저에 빈 화면이 뜬다 | 완료 |
| 1 | 게임 루프 | 1초에 60번 "계산하고 그리기", 경과 시간(dt) | 네모가 일정한 속도로 움직인다 | 완료 |
| 2 | 화면 | 작은 도트 화면(기본 320x180)을 깨지지 않게 확대 | 창 크기를 바꿔도 도트가 선명하다 | 완료 |
| 3 | 입력 | 키보드, 마우스 상태 읽기 | 화살표 키로 네모가 움직인다 | 완료 |
| 4 | 에셋 | 이미지 불러오기, 준비될 때까지 기다리기 | 그림 한 장이 화면에 나온다 | 완료 |
| 5 | 오브젝트 | 화면 속 "것"을 담는 틀(위치, 그리기, 할 일) | 여러 오브젝트가 각자 움직인다 | 완료 |
| 5.5 | 행동 블록 | 물건이 하는 일을 블록으로 골라 조합하기 | 코드 없이 새 적을 만든다 | 완료 |
| 6 | 카메라 | 화면보다 큰 세상을 따라가며 보여 주기 | 움직이는 대상을 화면이 따라간다 | 완료 |
| 7 | 글자와 게임 규칙 | 화면 글자, 점수, 목표, 제한 시간, 클리어/실패, 다시 하기 | 코인을 다 모으면 클리어, 시간이 다 되면 실패, 스페이스로 다시 | 완료 |
| 8 | 벽과 발판 | 중력, 점프, 단단한 물건에 막히기, 긴 바닥을 타일로 | 발판에 올라서고 벽에 막힌다 | 완료 |
| 9 | 애니메이션 | 가로로 붙인 그림을 넘겨 보여 주기, 상황별 애니메이션 | 걸을 때 다리가 움직이고 코인이 돈다 | 완료 |
| 10 | 소리 | 효과음, 반복되는 배경 음악, 소리 크기 | 점프, 코인, 클리어 때 소리가 난다 | 완료 |
| 11 | 장면 전환 | 장면 파일 여러 개, 타이틀, 다음 스테이지 | 타이틀 → 1스테이지 → 2스테이지 → 타이틀 | 완료 |
| 12 | 저장 | 창을 닫아도 남는 기록 | 최고 기록이 새로 고침 뒤에도 남는다 | 완료 |
| 13 | 내보내기 | 게임 전체를 파일 하나로 | game.html 하나를 두 번 누르면 게임이 열린다 | 완료 |
| 14 | 편집 도구 | 클릭으로 놓기, 끌어 옮기기, 블록 고르기, 장면 설정, 파일에 저장 | 화면에서 고치고 저장하면 JSON 파일이 바뀐다 | 완료 |
| 15+ | 써 보고 정하기 | 편집 도구를 써 본 느낌으로 다음 할 일을 정해요 | | |

## 결정 기록
- 2026-10-19: 8~14단계를 한 번에 진행. 이후는 편집 도구를 직접 써 보고 정한다.
- 2026-10-19: 편집 도구는 게임 화면 양옆에 붙는 패널(왼쪽: 놓을 물건, 오른쪽: 물건/종류/장면 탭). 고친 내용은 지금 장면에 바로 반영되고, 저장하면 kinds.json과 장면 파일에 쓴다(사람이 쓴 모양 그대로). start.bat으로 열었을 때만 켜지고 내보낸 게임에는 들어가지 않는다. 블록마다 이름(label)과 기본값(defaults)을 적어 두어 편집 도구가 목록과 입력칸을 만든다.
- 2026-10-19: 내보내기는 그림, 소리, 글꼴까지 넣은 HTML 파일 하나(export/game.html).
- 2026-10-19: 기록은 브라우저에 저장(settings.json의 saveName별). 장면별 최고 기록 = 클리어할 때 남은 초.
- 2026-10-19: 장면 파일 하나 = 장면 하나. 규칙이 없는 장면은 메뉴(스페이스로 next). 클리어 → next, 실패 → 같은 장면. 장면이 시작될 때 모듈의 enter가 불린다.
- 2026-10-19: 소리는 assets/sounds에 넣으면 이름으로 쓴다. 블록과 규칙에 sound 값, 장면에 music.
- 2026-10-19: 애니메이션 그림은 같은 크기 그림을 가로로 붙인 한 장(frames, fps). 어떤 애니메이션을 틀지는 블록이 정한다.
- 2026-10-19: 바닥과 벽도 물건이다(solid 블록). 장면 한 줄의 w/h로 그림을 타일처럼 늘린다. 예제 게임은 점프 게임으로.
- 2026-10-19: 글자는 한글 도트 글꼴 갈무리9(SIL OFL, 저작권 표시는 assets/fonts/Galmuri-LICENSE.txt)를 원래 크기로 써서 선명하게. 게임 규칙은 rules.json(모을 종류, 제한 시간, 문구). 점수는 블록이 올리고(vanish-on-touch의 score) 규칙이 읽는다. 끝나면 물건이 멈추고 action 키로 다시 시작.
- 2026-10-19: 맵 크기는 장면 파일의 size로 정한다(없으면 화면 한 장). 카메라는 camera-follow 블록이 붙은 물건을 따라가고 맵 밖은 보여 주지 않는다. 점수판처럼 화면에 고정할 것은 모듈에 fixed를 켠다.
- 2026-10-19: 물건이 하는 일은 행동 블록 조합으로 정한다. 종류는 kinds.json에 그림 + 블록 목록으로 적고, 장면 한 줄에서 블록 값을 그 물건만 바꿀 수 있다. 카메라보다 먼저 하기로 함.
- 2026-10-19: 오브젝트는 목록 방식. 모든 물건은 한 줄로 나란히 있고(먼저 적은 것이 뒤에 그려짐), 장면 파일에 종류와 위치만 적어 배치한다. 종류(kind)마다 폴더 하나. 물건끼리 붙어 다니기는 필요해지면 덧붙인다.
- 2026-10-19: 그림은 assets 폴더에 넣기만 하면 파일 이름으로 쓴다(목록 파일 없음). 없는 그림은 분홍 네모와 빨간 안내 띠로 알려 주고 게임은 멈추지 않는다.
- 2026-10-19: 게임은 키를 직접 묻지 않고 "동작 이름"(left, action...)으로 묻는다. 키 배치는 controls.json에서 바꾼다. 한 동작에 키 여러 개 가능.
- 2026-10-19: 확대 방식은 두 가지. sharp(정수배, 기본값: 도트가 모두 같은 크기, 가장자리에 여백) / fill(창에 꽉 차게, 도트 크기가 미세하게 고르지 않을 수 있음).
- 2026-10-19: 특정 게임(예전 기차 게임)이나 다른 엔진(Godot)을 기준으로 삼지 않는다. 화면 크기도 설정값으로 두고 기본은 320x180.
- 2026-10-19: PR과 커밋 설명은 한국어로. 설명은 사용하는 사람 입장에서.
- 2026-10-19: 실행 도구는 Vite(저장하면 화면이 바로 바뀜) + TypeScript 두 가지만. 모듈은 init, update(dt), draw 세 순간에 끼어든다.
- 2026-10-19: 기존 엔진과 에디터를 지우고 처음부터 다시 시작. 에디터는 맨 마지막에.
